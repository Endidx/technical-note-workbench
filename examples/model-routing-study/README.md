# 什么时候需要让模型参与笔记升级？

这次配对实验把同一批 15 篇笔记各审阅两遍。只用规则时，11 篇的动作与补丁符合金标。允许模型参与 KMeans 的意图判断后，13 篇符合金标。新增的两篇分别是从原文确认采用新版默认值，以及从原文确认升级后仍要使用十次初始化。[冻结数据](frozen/README.md) · [逐案输出、模型响应与访问记录](results.json)

| 指标 | 规则 | 规则＋按需模型 |
| --- | ---: | ---: |
| 动作与补丁正确 | 11 / 15 | 13 / 15 |
| KMeans 正确 | 6 / 10 | 8 / 10 |
| OneHotEncoder 正确 | 5 / 5 | 5 / 5 |
| 应改且给出正确补丁 | 4 / 6 | 5 / 6 |
| 误建议修改 | 0 | 0 |
| 漏改 | 2 | 1 |
| 多余追问 | 3 | 1 |
| 应追问且返回追问状态 | 4 / 5 | 4 / 5 |
| 阻塞／运行错误 | 1 / 0 | 1 / 0 |
| 实际调用模型的笔记 | 0 | 5 |
| 服务端收到的模型请求 | 0 | 13 |

误建议修改计入不应修改却给出正文，或应修改但给出错误正文的情形。漏改是应改却没有给出有效补丁。多余追问是金标为保留或修改却转为追问。阻塞和错误始终占用分母。本轮所有正确补丁都逐字匹配冻结参考全文。

## 输入与实际执行

冻结文件清单的 SHA-256 是 `22bd2705d2e0148e87fb41684d1a7ee9f057e63c5b28906413ad38e377b52532`。所有正文和金标在推理前已确定。样例由同一 AI 助手逐篇设计并预标，按待覆盖的迁移情形挑选。该样本规模、单次运行和单一模型只支持这 15 篇的配对对照。

运行器直接从正文里唯一的 Python 代码块读取 sklearn 导入来选择 API。两组按相同条件受理每篇笔记。调用端只接收文件名、正文、相同类别的相同资料和适用的运行参数。实验任务是升级到目标版本，两个底层调查接口都通过方法和资料版本指定这项操作，接口没有自由文本指令参数。金标仅由评分步骤读取用于判断预测。

- KMeans 两组都用单篇 `harness.run`、离线工具规划、修订号 0，分别传 `intentMode="rule"` 或 `"model"`。单篇接口会逐字核验导入资料。为适配这一限制，两组都显式传入哈希一致的 1.1.3 和 1.4.2 专用 KMeans 摘录，实验目录另存了检查点加载的 1.0.2 辅助资料。[单篇版本快照](sources/harness/)
- OneHotEncoder 两组都用 `library.investigate_batch_note`，传入冻结方案中列出的综合资料。每条路由只使用所属的版本资料。[批次版本快照](sources/batch/)
- 引擎 Git 树为 `a875e78148ce6737d4d9d7b7bb72b1a3e2c85a68`（`747123f:analyzer`）。实测环境为 Apple Silicon、Python 3.9.6、llama.cpp b6650（`7c156df4`）、Qwen2.5-3B-Instruct Q4_K_M。权重 SHA-256 为 `626b4a6678b86442240e33df819e00132d3ba7dddfe1cdc4fbb18e0a9615c62d`。服务绑定回环地址，使用 8192 上下文、温度 0、种子 42。
- 实测逐篇串行执行，比较调用捕获记录和专用服务器同一时间段的访问日志。模型响应别名全部为 `notes-qwen-3b`，13 条调用均有 HTTP 200。在输出中可检查每篇的原始终态、工具轨迹、模型阶段、响应正文和对应的服务端日志行。[运行器](run.py) · [原始结果](results.json)

## 复现

在仓库根目录的第一个终端启动专用模型服务并记录访问日志。首次执行会下载权重。在其他平台需按仓库说明提供相同版本的 llama-server。[模型启动脚本](../../scripts/start-eval-model.sh)

```sh
./scripts/start-eval-model.sh 3b > /tmp/workbench-routing-llama.log 2>&1
```

待服务就绪后，在第二个终端运行。保持该服务只处理这一项实验，以便逐案比对服务端日志。

```sh
curl -fsS http://127.0.0.1:18087/health
(cd examples/model-routing-study/frozen && shasum -a 256 -c SHA256SUMS)
python3 -B examples/model-routing-study/run.py \
  --weights .runtime/benchmark/intent-3b.gguf \
  --server-log /tmp/workbench-routing-llama.log \
  --output /tmp/workbench-routing-replay.json
```

本次保存结果的 SHA-256 为 `1eacf9bff724e017763209491fe58146fd7f23a15f1fef6ce29a17e3557cf1ee`。复跑时按逐案动作、补丁、调用审计和汇总计数进行对照。时间戳、响应 ID 和计时属于单次运行记录。
