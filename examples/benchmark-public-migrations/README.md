# GitHub 下游迁移决策留出集

七条记录来自七个不同下游项目，每个项目只取一次提交、一个调用点。三条 edit、两条 keep、两条 ask。可见输入仅为 notes/ 下的笔记。gold.json 是人工金标，sources.json 是逐条证据索引，含项目、提交 SHA、父 SHA、父版本文件行号及固定链接、原始理由短摘、实际改动、可见信息范围和许可证。

## 采样和评分单位

2026-11-23 使用 GitHub 公开提交搜索，查询为 `"n_init" "KMeans" committer-date:2022-01-01..2025-12-31`，相关性排序、每页 100，返回总数 484。仅检查第一页中的目的抽样候选，跳过上游 scikit-learn、明显镜像和重复提交。逐份核对最终 diff、父版本源码及 sklearn 导入；只取能固定父行号、能说明变化且能取得当时许可证的 Python 调用。多处同改只计一条，未使用项目内部笔记。本集合不是随机样本，不估计真实请求的类别比例，也不提供线上成功率。

这里的维护问题是，在指定为 1.4.2 的环境下，这个调用是否需要显式使用十次初始化。edit 表示需添加或改写为 10，keep 表示父版本调用在题设环境中已经满足所选策略，ask 表示可见证据不足以决定策略。该口径只判初始化语义。实际项目如果另有显式写参数或消除旧版本警告的要求，keep 不能重建其完整补丁。p04 涉及把显式的 1 改为 10，属于不同实现的测试配置对齐，覆盖与默认值迁移相邻的调用修订。未假定所有项目实际都从 1.1.3 升级到 1.4.2。
