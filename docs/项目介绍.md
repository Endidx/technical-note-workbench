# 技术笔记迁移审阅工作台

依赖库升级后，笔记里的代码即使仍能运行，也可能产生不同的结果。工作台把两版资料和一批 Markdown 笔记放在同一个审阅页面，逐篇列出版本引文、受影响的调用和建议差异。用户可以补充配置、接受部分修改，然后导出整批笔记。[五篇示例与操作指南](../GUIDE.md#审阅五篇升级笔记)

## 如何处理一次升级

| 环节 | 实现与取舍 |
| --- | --- |
| 导入与检索 | Java 接收版本资料和笔记，索引构建完成后发布快照。检索以倒数排名融合 BM25、向量和 Python AST 标识符，返回命中段落及行号。默认概念向量可离线使用，可选 ONNX 多语言 MiniLM。 |
| 批量调查 | 任务固定快照与版本对，有界并发扫描全部笔记。Python 解析 AST、归属关系和笔记意图，生成建议或提出具体问题。一篇需要补证时，其他笔记可以继续。 |
| 恢复与确认 | 后台逐篇保存结果，使用租约核验执行者资格。审阅者补入一篇缺失的配置后，只重新调查该篇。导出按接受状态逐篇选择正文。 |
| 运行环境 | 本地使用 Java 17、Spring Boot、H2、Python 和随包 React 前端。Compose 提供 FastAPI、MySQL、RabbitMQ、MinIO、Qdrant 的部署方式。 |

## 已测结果

- **检索。** 27 篇笔记、11 个查询中有 9 个带相关文档。在这 9 个查询上，BM25 的宏平均 Recall@5 为 71.1%，BM25 加 MiniLM 为 87.8%。加入 AST 通道后仍为 87.8%。另两个查询的参考答案为空。[相关性标注和各通道结果](../examples/retrieval-eval/README.md)
- **并发与恢复。** 同机器上的三组配对中，25 篇笔记从单路中位数 1.601 秒降至四路 0.507 秒，每篇结果一致。中断时已提交 4 篇，恢复后只执行其余 21 篇。25 篇来自五类模板，计时覆盖本机 H2 和真实 Python 子进程。[实验设置及逐组记录](../examples/batch-performance/README.md)
- **参数改名。** 六个独立下游项目各提供一个改名前调用和一个已迁移调用，12 个输入全部得到预期修改或保留。样本按提交中出现明确参数替换筛选。共享字典、动态键等问题另有 14 个定向回归用例。[公开迁移回放](../examples/public-encoder/README.md) · [配置归属回归](../examples/batch-decisions/README.md)
- **意图判断。** 在八篇公开 KMeans 迁移笔记上，离线单篇调查首次动作正确 4 次，漏掉了全部 3 个应改项。作者提出保留旧默认值时，系统有时仍会要求补充说明，或保留有误的显式参数。[案例来源和标签](../examples/benchmark-public-reference-final/README.md) · [复现命令](../GUIDE.md#复验)
